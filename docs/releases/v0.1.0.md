# Small Chain v0.1.0 release notes (candidate)

**Status: release candidate; v0.1.0 is not tagged or published.** These notes
describe the bounded portfolio scope intended for the first release. The tag
must point to a later immutable `main` commit whose own six-job CI run is green.

## Why this release exists

Small Chain demonstrates the platform work behind a background-job system:
bounded admission, explicit failure semantics, durable scheduling, crash
recovery, operator inspection and evidence-backed operations. It deliberately
keeps one Go API, one Go worker and one PostgreSQL source of truth instead of
adding brokers, orchestration layers or blockchain components.

## Highlights

- Fixed-size Go worker pools, bounded queues and retained-record limits expose
  overload instead of growing work without a limit.
- Memory mode provides a five-minute retry, idempotency, cancellation and
  shutdown demo; PostgreSQL mode commits acceptance before HTTP 202.
- Durable workers use short `SKIP LOCKED` claim transactions, leases,
  heartbeats and owner/version fencing. Expired work is recovered with
  at-least-once execution semantics.
- The React/TypeScript console lists and filters durable jobs, reads retained
  lifecycle events and performs confirmed cancellation without optimistic
  terminal state.
- Prometheus/Grafana, optional bounded OpenTelemetry export, controlled load
  collection and a worker-SIGKILL drill provide reviewable operational
  evidence with explicit limits.

The shortest review path is the [portfolio evidence index](../evidence.md).

## Run modes and upgrade notes

The default command starts the in-memory demonstration and does not require a
database. Restarting it loses jobs, results and idempotency keys.

```sh
make run
```

Durable mode is opt-in. Set `DATABASE_URL`, apply migrations explicitly, then
start the API and at least one worker with a unique owner. The migration command
is safe to rerun and CI executes it twice. Existing numbered migrations must not
be edited after release; schema changes add a new migration.

```sh
make migrate
go run ./cmd/small-chain -storage=postgres
go run ./cmd/small-chain-worker -owner=worker-a -metrics-addr=127.0.0.1:9091
```

This is the first tagged-release candidate, so there is no supported upgrade
contract from an earlier version. The [PostgreSQL guide](../postgres.md) and
[runbook](../runbook.md) define startup order, retention, recovery and teardown.

## Compatibility and dependency review

- Build toolchain: Go 1.27.3 from `.go-version`; module language baseline:
  Go 1.27.0.
- Durable CI database: PostgreSQL 16.
- Console CI toolchain: Node.js 24.19.0 and real Playwright Chromium.
- PostgreSQL driver: pgx v5.12.0 or later. The reviewed floor includes the
  upstream simple-protocol batch and authentication/channel-binding fixes.

The repository does not use pgx `SendBatch`, the simple-protocol batch mode or
custom `BatchResults`. Dependency upgrades still run the full PostgreSQL,
process-recovery and browser workflow because pgx remains part of every durable
state transition.

## Security and deployment boundaries

- The server has no authentication, authorization or TLS termination. Bind it
  to loopback or place it behind controls appropriate to the environment.
- Credentials in `compose.yaml` are local demonstration values. PostgreSQL is
  not published to the host by the Compose stack.
- `demo.checksum` accepts bounded text and never executes shell commands,
  containers, arbitrary code or outbound HTTP requests.
- Trace attributes exclude payloads, idempotency keys, worker owners, error
  bodies and baggage; tracing is optional and cannot determine readiness.
- Cancellation is cooperative. Fencing protects PostgreSQL state but cannot
  make an arbitrary external side effect exactly once.

This release makes no claim of authenticated multi-tenancy, multi-region
failover, disaster recovery, production availability, an SLO, a latency
percentile or production-scale throughput.
